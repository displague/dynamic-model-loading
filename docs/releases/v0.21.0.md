# Screen novel-loading candidates in minutes before long matrices

This release adds and validates a **five-minute supervised screen** for physical
loading research. It does not invent a new policy or claim an inference speedup.
The already negative v0.20 pager is the known control for testing the workflow.

## Result

The fixed subset finishes in **3 minutes 22 seconds**, including 195.308 seconds
of worker startup, checks, warmups and measurements plus 6.774 seconds of independent
analysis. Two prompts, eight output tokens each, one repeat and the eager/prefetch
512 MiB pair replace another hours-scale performance matrix for this screen only.

- All four scored outputs and both paged warmups match the dense reference.
- Both conditions accept **6/40 proposals (15%)**, below the frozen 50% screen.
- Prefetch transfers **5.6642% more data**, failing the required 10% saving.
- Scored wall time is 75.371 seconds for prefetch versus 69.884 for eager;
  the two dense references total 0.475 seconds. Different output caps mean these
  times are not speedup comparisons with the old 64-token episodes.
- The decision is **stop**. No long matrix or llama.cpp patch was launched.

This is retrospective screening-workflow validation using known diagnostics and
the unchanged frozen calibration index. It is not held-out confirmation, target-scale
evidence or satisfaction of the historical native-pivot gate. Novel-loading
research remains open; future distinct candidates need their own frozen short
screen and a separate expanded protocol if promising.

## Implementation and validation

An owned-worker supervisor enforces a 300-second limit including loading and
checks. Timeouts and incomplete/corrupt receipts are inconclusive, never passes.
The harness has no automatic full-matrix launch. A pass only permits proposing an
expanded study. All proposal waste, dense verification, physical pages, staging,
controller, target/draft memory and resource samples are charged and retained.

All 28 FFNs pass the two-position numerical smoke check; both full-model logit
positions pass. Independent replay verifies all six paged episode ledgers and
produces identical results. Peak total GPU use is 8,583.098 MiB; all 957 resource
samples satisfy the fixed limits. The reviewed, pushed pre-inference source is
[`1f5bd89`](https://github.com/displague/dynamic-model-loading/commit/1f5bd89ae32f31942facdd4022ce69c6a1ec64a8).
The pre-inference CPU suite passes **350 tests**. Independent code review found
and corrected adapter-hook, final-position and receipt-validation gaps before
measurement. Historical v0.20 inference and 27/32/64 replay defaults are unchanged.

Run the short screen from the prepared project environment with a fresh directory:

```powershell
.\.venv\Scripts\python.exe -m dynamic_model_loading.fault_screen --output runs/fault-screen-<fresh-name>
```
