# v0.11.0 - Chat formatting recovers task successes; balanced qualification still fails

Qwen's documented chat interface succeeds on **7/10 old debug tasks** and **12/20
fresh balanced development tasks**, while matched plain text remains **0/10**.
All three dense paths reproduce the same continuations. This isolates a material
interface problem without explaining away the remaining substantive errors.

| Question | Finding |
|---|---|
| Useful behavior under chat formatting? | 7/10 old and 12/20 fresh successes. |
| Does the custom incremental path preserve native generation? | Yes, all 40 pairs. |
| Does fully retained repacking/instrumentation preserve it? | Yes, all 40 pairs. |
| Frozen Gate A satisfied? | **No:** 12/20 is below 14/20; topic changes are 1/4, below 2/4. |
| Physical paging authorized by this result? | No; complete-policy quality and economics remain separate gates. |

Fresh domain successes: code 2/4, extraction 4/4, arithmetic 3/4, copying 2/4,
topic changes 1/4. Correctness, format compliance and their conjunction are reported
separately under frozen scalar-answer rules. All raw continuations are retained,
including answers that convey a correct choice in an unacceptable format.

The paired comparison uses identical greedy decoding, a neutral repetition penalty,
64-token cap and model EOS stops. Native library prefill, custom incremental prefill,
and fully retained popularity-packed execution are compared. Across the 80 path
comparisons, maximum aligned-logit relative L2 is 1.1216041e-05, maximum mean KL is
3.8351987e-10, and all generated continuations match exactly. No sparse execution or
runtime performance is measured here.

The [protocol](https://github.com/displague/dynamic-model-loading/blob/v0.11.0/docs/dense-interface-protocol.md), source and both task sets
were committed before measurement. v0.10 remains the unchanged plain-text
exact-output control; the changed decoding means cross-release differences cannot
be attributed to formatting alone. These are small development fixtures, not
held-out agent quality or executable-code evaluation.

The [three-gate decision](https://github.com/displague/dynamic-model-loading/blob/v0.11.0/docs/adr/0002-qualified-utility-and-causal-evidence.md)
keeps analytical repair independent of utility qualification. Complete-policy
quality and fully charged acquisition batches govern a later bounded runtime
experiment. [#21](https://github.com/displague/dynamic-model-loading/issues/21)
closes the bounded interface experiment; [#8](https://github.com/displague/dynamic-model-loading/issues/8)
and [#19](https://github.com/displague/dynamic-model-loading/issues/19) remain open.

Validation: independent review, complete raw-grid and restored-asset reanalysis,
and **188 passing tests** on the final clean candidate in both PyTorch 2.10.0+cu130
and 2.12.0+cu130. The measured GPU run uses only the frozen 2.10 environment.
