# Physical draft paging: correct outputs, negative acquisition result

This release builds and measures a **custom PyTorch weight-loading path**, not an
optimized llama.cpp configuration. A causal FFN-input side index selects physical
host-backed draft pages; an explicit GPU cache acquires them, and an independent
dense target verifies every committed token.

The full frozen experiment is complete. **All 72 scored outputs match the dense
reference**, and all numerical, page-accounting and resource checks pass. The
tested policy nevertheless fails: every candidate accepts only **456/1512 proposals
(30.1587%)**, both LRU budgets have zero demand hits, and prefetch adds traffic.
The original physical-improvement decisions and ADR 0005 native-admission predicate
fail. No threshold, prompt, candidate or run is replaced.

## Measured results

Each row is twelve episodes: four prompts by three repetitions, 768 committed
tokens. Episode wall time includes the 32-token prefix and 64 generated tokens,
drafting, verification, rejected proposals, page gathering/copying and control.
Model startup and excluded warm-ups are outside these episode aggregates.

| Policy / cache MiB | Median episode seconds | Committed tokens/second | Draft H2D GiB/committed token |
|---|---:|---:|---:|
| Resident dense target |1.416|45.116|0|
| Eager / 128 |115.800|0.5654|9.5385|
| Eager / 512 |115.743|0.5651|9.5385|
| LRU / 128 |117.737|0.5556|9.5385|
| LRU / 512 |119.762|0.5454|9.5385|
| Prefetch / 128 |123.385|0.5286|10.1422|
| Prefetch / 512 |124.454|0.5258|10.0444|

Prefetch increases total transferred bytes by **6.3291% at 128 MiB** and
**5.3032% at 512 MiB** versus the equal-budget LRU/eager controls. At 512 MiB,
7,737 demand hits do not repay 88,404 unused prefetched pages. Its median episode
is 3.9177% slower than LRU. Target computation accounts for 15.803 of its 1460.595
total seconds; synchronized gathering/copy intervals account for 916.728 seconds.
The zero for target-only means no draft-page traffic, not no model-loading or PCIe
traffic. Detailed receipts retain separate demand/prefetch bytes and all timings.

## What is and is not established

The 28 layer checks and 16 full-model checks pass unchanged tolerances. Worst FFN
relative L2 is 2.709208e-7; worst full-logit relative L2 is 1.593579e-6; worst mean KL
is 5.265001e-8. All 45,198 resource samples pass: peak device use 8664.418 MiB is below
15000 MiB, and minimum available host memory 8537.672 MiB is above 2048 MiB.
Actual page payloads peak at 4.5, 126 and 508.5 MiB for eager, 128 and 512 MiB caches.
Target/draft weights are independent; CPU source, both controller copies, staging,
KV, metadata and allocator costs are retained and charged.

This uses the pinned Qwen2.5-1.5B-Instruct FP32 checkpoint in the unchanged root
Python 3.14.3 / PyTorch 2.10.0+cu130 / Transformers 5.13.1 environment on the RTX 5080
Laptop GPU. The dense target fits on GPU; draft residency is artificially bounded.
This is **not a 32B speedup, deployable runtime, agent-utility result or global
novelty claim**. Existing stock 32B configurations remain practical baselines, not
direct throughput controls for these different FP32 weights. Synchronous prefetch
does not establish overlap. A transient monitoring-shell failure did not restart
the measured Python process; shared-machine timing limitations are documented.

## Reproduction and disposition

The [protocol and implementation](https://github.com/displague/dynamic-model-loading/tree/26bee331b9b8fd34ddbbfa4364e95c12f4700511)
and [prospective amendment](https://github.com/displague/dynamic-model-loading/blob/26bee331b9b8fd34ddbbfa4364e95c12f4700511/docs/fault-pager-amendment-1.md)
were reviewed and pushed before calibration. The independent model-free analyzer
reconstructed the index, numerical gates, page-demand/LRU state, KV commits, frozen
matrix and resource receipts. The full test suite passes 325 checks. Raw evidence
is preserved in four ZIP assets containing 411 files; every member was decompressed
and SHA-256 checked against the analyzed run. The compact archive inventory records
each asset's hash and byte count.
A second model-free audit reproduced the summary and all-file inventory byte-for-byte.

This completes the bounded experiment [#35](https://github.com/displague/dynamic-model-loading/issues/35),
not the broader [novel-loading milestone](https://github.com/displague/dynamic-model-loading/milestone/10).
The original research question remains open. The next experiment must change
acquisition representation or residency lifetime and improve verified tokens per
transferred byte under a fresh protocol, with an explicit departure from prior
work. Porting this failed policy or resuming stock flag sweeps is not the next step.
No llama.cpp clone, worktree, patch or custom native build was created.
