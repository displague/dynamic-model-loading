# Feedback-directed correction loading: a new candidate, a negative short result

This release implements and measures a distinct loading strategy in PyTorch:
compute all FFN neurons from a resident two-bit base, then fetch full-precision
correction pages according to estimated output error, updating the acquisition
decision with each observed correction. It is not stock llama.cpp flag tuning.
Low-bit bases and residual acquisition have antecedents; this release does not
claim their invention or establish global novelty for the feedback policy.

## Result in plain terms

The corrected screen takes **2 minutes 14 seconds**, including a 125.438-second
worker and 8.703 seconds of independent analysis. Two known prompts, eight prefix
tokens and eight output tokens each; one repeat, four controls, fixed five-minute
worker limit. All scored and warmup outputs match the dense target.

| Draft condition | Accepted proposals | Scored wall seconds | Page transfers GiB |
|---|---:|---:|---:|
| Stream every full page | 16/16 | 25.093 | 137.8125 |
| Two-bit base only | 0/64 | 12.571 | 0 |
| Fixed four-page corrections | 0/64 | 23.515 | 46.265625 |
| Feedback-directed corrections | 0/64 | 24.313 | 46.265625 |

Each row produces the same 16 committed tokens. Approximate controls achieve
exact final output through **dense fallback**, not useful draft acceptance.
Feedback is 93.40% slower than the base and 3.39% slower than fixed selection,
with identical traffic to fixed selection. Saving traffic versus dense streaming
alone is insufficient. Four required policy checks fail; the decision is **stop**.
No long performance matrix or llama.cpp patch was launched.

## What the evidence establishes

All-page corrections reconstruct the 56 tested FFN inputs and both full-model
logit positions within frozen tolerances. Actual transfer ledgers, causal policy
choices, accepted-prefix/KV records, charged timings and source hashes replay
independently. Peak extra CUDA allocation is 619.125 MiB under the 768 MiB budget;
all 734 joint resource samples pass. The resident dense target reference takes
0.416 seconds, so this is not acceleration over that reference or a 32B result.

Local mean FFN error falls from 1.216407 for the base to 0.980107 for feedback,
but fixed correction does better at 0.945419; neither yields an accepted proposal.
This is evidence against the tested two-bit/four-page candidate, not proof that
every residual-loading design fails. The broad novel-loading program stays open.

The first 138.939-second worker is preserved with an **inconclusive** decision:
its original accounting rule assumed too little baseline overhead. A separate,
prospectively pushed correction charges all overhead inside the same allowance;
it changes no policy, workload or economic threshold. All 29 constructed artifact
hashes match between attempts. The corrected source freeze is
[`bb34a8f`](https://github.com/displague/dynamic-model-loading/commit/bb34a8f91dbf5fc2b7f4cc210affab7b98480780).
Original receipts and published history are not rewritten.

## Validation and evidence

The corrected pre-inference CPU suite passes **384 tests**. Independent reviews
approved the implementation and accounting correction; a second model-free replay
reproduces the entire corrected summary exactly. Review strengthened observed
feedback/rollback tests, charged timing and physical memory lower bounds.
