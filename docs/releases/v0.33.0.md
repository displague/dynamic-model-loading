# v0.33.0 - Compact exact-active-row packets pass the physical-loading screen

Third of six authorized deliveries. The corrected **25.177-second** screen passes
both gates. Actual weight-plus-index H2D falls **93.65%**, and wall time falls
**69.36%** against dense streaming. Both comparisons also beat128-row sparse
acquisition. Every checked full-logit value and emitted token matches the original
dense reference exactly on the completed corrected workload.

|---|---:|---:|---:|
| Streaming | 16 | 25,769,803,776 B | 2.142871s |
| 128-row sparse extents | 16 | 22,376,611,840 B | 2.088562s |
| Compact active-row packet | 16 | 1,635,580,200 B | 0.656515s |
| Restored resident | 16 | 0 B | 0.168545s |

Compute the first projection fully, observe exact zeros, gather active outgoing
rows plus indices into one packet, transfer once and scatter into the original
dense workspace. Dense linear computation remains; this is real acquisition, not
a proxy traffic simulation, learned selector, custom kernel or llama.cpp flag study.
Packet is3.26x as fast as this streaming control but still3.90x slower than the
restored resident. Two short pretrained-OPT continuations do not establish task
quality, general speedup, long-context behavior or larger-model access.

The first attempt stopped after18.089s: IDs matched, but one logit error exceeded
the unchanged1e-5 tolerance. Its six partial episodes remain inconclusive and are
archived. A reviewed fresh protocol restored original weight layout and F.linear
for ALL conditions; prompts/order/gates stayed identical. Corrected run19.111s +
audit6.066s passes, with zero logit error in six hybrid and two restored episodes.
The prompts are known/reused after that failure, not an untouched holdout. Exact
second audit uses no new inference. **579 CPU tests pass**; final clean-tip XML and
validation are attached separately.
